====================================================================

Phiên bản tài liệu: 2026-08-09

Tài liệu này hướng dẫn đưa feature KPI Management từ prototype vào solution
ASP.NET Core MVC dùng C#, Razor .cshtml và PostgreSQL. Đọc theo đúng thứ tự.

1. KẾT QUẢ SAU KHI TÍCH HỢP
--------------------------------

Feature cung cấp:

- KPI Definition có code, name và description.
- KPI Version Draft; Version đã submit/approved/published là immutable.
- Formula Variable có code, display name, type Decimal/Boolean, required,
  default, description và display order.
- Formula source được server biên dịch thành AST có version; không dùng eval.
- Phép tính toán học, so sánh, AND, OR, NOT, IF, ROUND, ABS, %, MOD.
- Submit, approve/reject, publish, effective_from, retire, archive/restore,
  transfer ownership và Audit Record.
- KPI Period: draft, chọn đúng Definition + Version, submit, approve, activate,
  close và amendment/review.
- Official KPI Evaluation bất biến và Superseding Evaluation khi correction.
- Test Run chỉ hiển thị kết quả; không lưu Evaluation.
- Khi mở một KPI có Draft đã lưu, editor tự nạp variables + formula source.
  AST tự validate và hiển thị sau khi trang mở.

Phân biệt dữ liệu:

- Test Run gọi POST /api/v1/formulas/test-run và trả persisted=false.
- Definition, Version, Period, Evaluation và Audit đi qua PostgreSQL khi runtime
  profile là Postgres.
- InMemoryTest chỉ dành cho test/demo; restart process sẽ mất dữ liệu.

6. ĐĂNG KÝ APPLICATION + POSTGRESQL
------------------------------------

Trong Program.cs/Startup của project lớn, gọi AddKpiPostgres và đăng ký các
operation với cùng KpiRuntimeState:

    builder.Services.AddKpiPostgres(builder.Configuration);
    builder.Services.AddSingleton<KpiRuntimeState>();

    builder.Services.AddScoped<KpiOperations>(sp => new KpiOperations(
        sp.GetRequiredService<KpiRuntimeState>().Store,
        sp.GetRequiredService<IClock>(),
        sp.GetRequiredService<IKpiDefinitionPersistence>(),
        sp.GetRequiredService<IKpiGovernedPersistence>()));

    builder.Services.AddScoped<PeriodOperations>(sp => new PeriodOperations(
        sp.GetRequiredService<KpiRuntimeState>().Store,
        sp.GetRequiredService<IClock>(),
        sp.GetRequiredService<IKpiGovernedPersistence>()));

    builder.Services.AddScoped<EvaluationOperations>(sp => new EvaluationOperations(
        sp.GetRequiredService<KpiRuntimeState>().Store,
        sp.GetRequiredService<IClock>(),
        sp.GetRequiredService<IKpiGovernedPersistence>()));

Đổi namespace theo solution lớn. Không đăng ký InMemoryKpiStore làm persistence

8. POSTGRESQL, ROLE VÀ MIGRATION
---------------------------------

Tên configuration phải thống nhất:

    ConnectionStrings:KpiMigration = role kpi_migrator
    ConnectionStrings:KpiRuntime   = role kpi_runtime
    Kpi:PersistenceProfile         = Postgres

PowerShell local (thay secret thật ngoài Git):

    $env:ConnectionStrings__KpiMigration = "Host=localhost;Port=5432;Database=kpi_lab;Username=kpi_migrator;Password=<local-secret>"
    $env:ConnectionStrings__KpiRuntime = "Host=localhost;Port=5432;Database=kpi_lab;Username=kpi_runtime;Password=<local-secret>"
    $env:Kpi__PersistenceProfile = "Postgres"
    $env:Kpi__EnableDevelopmentSeed = "true"

Quyền:

- kpi_migrator tạo schema, index, constraint và ghi kpi_schema_migrations.
- kpi_runtime chỉ đọc/ghi dữ liệu nghiệp vụ cần thiết.
- kpi_runtime không ALTER, DROP, TRUNCATE hoặc sửa/xóa audit_records.
- Web startup không chạy migration.

Prototype:

    .\harness.cmd bootstrap
    .\harness.cmd migrate

Solution lớn:

    dotnet run --project tools/Company.Kpi.Migrator/Company.Kpi.Migrator.csproj --configuration Release --no-restore

Lệnh Migrator in MIGRATION_TARGET, MIGRATION_APPLIED và MIGRATION_SKIPPED.
Migration runner chỉ cho database đã được allow-list (mặc định kpi_lab và
kpi_lab_test). Nếu project lớn dùng tên DB khác, lập ADR và cập nhật allow-list
trước khi chạy; không bỏ allow-list.

Trong pgAdmin 4, refresh database/schema và kiểm tra:

    kpi_schema_migrations
    kpi_definitions
    kpi_versions
    kpi_periods
    kpi_period_activations
    kpi_period_amendments
    kpi_evaluations
    audit_records

SQL kiểm tra:

    SELECT id, code, name, organization_id
    FROM kpi_definitions ORDER BY code;

    SELECT id, definition_id, version_number, status,
           formula_json, variables_json
    FROM kpi_versions ORDER BY version_number;

formula_json là object source + AST; variables_json giữ code, thứ tự, type,
required, default và description.

10. KIỂM THỬ UI TỪNG BƯỚC
-------------------------

1. Chạy Web với profile Postgres.
2. Mở /Kpis/Create, tạo code REVENUE_ACHIEVEMENT.
3. Nhập Variables:

       revenue
       target

4. Nhập Formula:

       ROUND(revenue / target * 100, 2)

5. Diagnostics không có lỗi; AST xuất hiện.
6. Bấm Lưu phiên bản Draft.
7. Reload hoặc quay lại /Kpis rồi bấm lại KPI.
8. Xác nhận textarea vẫn có revenue, target và source nguyên thứ tự.
9. Xác nhận form có action /Kpis/UpdateDraft.
10. Nhập revenue=130, target=100 rồi bấm Chạy Test Run.
11. Xác nhận kết quả theo formula và thông báo không lưu Evaluation.
12. Kiểm tra PostgreSQL: Test Run không tạo row kpi_evaluations.

Governance journey:

1. Creator submit Version.
2. Approver khác Creator approve/reject kèm comment.
3. Chỉ Approved mới publish; effective_from không được overlap.
4. Tạo Period, chọn đúng Version, submit và approve.
5. Activate khi tới thời điểm hiệu lực.
6. Tạo Official Evaluation; kiểm tra history và Current.
7. Correction thành công tạo Superseding Evaluation; correction lỗi không thay
   Current.
8. Mở Audit timeline và kiểm tra actor, event, reason, timestamp.

11. API SMOKE TEST
------------------

POST /api/v1/formulas/validate với body:

    {
      "source": "IF(revenue > target AND active, ROUND(revenue / target * 100, 2), 0)",
      "declaredResultType": "Decimal",
      "variables": [
        {"code":"revenue","displayName":"Revenue","type":"Decimal","required":true},
        {"code":"target","displayName":"Target","type":"Decimal","required":true},
        {"code":"active","displayName":"Active","type":"Boolean","required":true}
      ]
    }

Response hợp lệ phải có valid=true, formula.source, formula.ast,
formulaLanguageVersion và astSchemaVersion.

POST /api/v1/formulas/test-run với body:

    {
      "source": "ROUND(revenue / target * 100, 2)",
      "declaredResultType": "Decimal",
      "variables": [
        {"code":"revenue","displayName":"Revenue","type":"Decimal","required":true},
        {"code":"target","displayName":"Target","type":"Decimal","required":true}
      ],
      "inputs": {"revenue":"130","target":"100"}
    }

Response thành công:

    {"persisted":false,"outcome":{"kind":"Success","value":"130"}}

Decimal trong JSON là chuỗi invariant, không binary floating point.

13. TROUBLESHOOTING
-------------------

Editor rỗng:
- Kiểm tra KpisController.Edit có operations.List(organizationId).
- Kiểm tra có Draft và status đúng không.
- Kiểm tra textarea asp-for Variables/Source.
- Kiểm tra hidden VersionId/ConcurrencyToken.

- Kiểm tra Network POST /api/v1/formulas/validate.
- Kiểm tra formula-editor.js có scheduleValidation lúc init.
- Kiểm tra đúng các element ID.
- Đọc diagnostics code/message/span; không bypass lỗi bằng client AST.

- Refresh đúng database/schema.
- Kiểm tra ConnectionStrings__KpiMigration.
- Chạy Migrator, không chỉ chạy Web.
- Đọc MIGRATION_TARGET/APPLIED.

- Đang dùng InMemoryTest.

- Chạy migration rồi restart Web.

HTTP 400/403:
- Kiểm tra antiforgery, ActorContext, organization scope, capability và
  separation of duty.

Locked restore lỗi:
- Không chạy use-lock-file thường xuyên.
